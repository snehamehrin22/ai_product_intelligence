# Progress Log - Phase 2: Event Instrumentation

## Codebase Patterns

- **Zerobus Event Publishing**: Use `ZerobusPublisher` dependency injection with FastAPI `Depends()` for event publishing
- **Fire-and-forget pattern**: Events published via `BackgroundTasks` to avoid blocking API responses
- **Session ID extraction**: `request.headers.get('X-Session-Id', str(uuid.uuid4()))` pattern for session tracking
- **Event properties**: Store event-specific data in nested `properties` field (flexible JSON structure)

### Learnings for future iterations:
- **Pattern**: Use dependency injection (`Depends(get_zerobus_publisher)`) for clean publisher access in endpoints
- **Pattern**: Fire-and-forget event publishing via FastAPI `BackgroundTasks` prevents blocking API responses
- **Gotcha**: Only emit task_completed event when transitioning TO completed status (not when toggling back to pending)
- **Context**: Task completion toggle endpoint provides cleaner UX than requiring full PUT update
- **Pattern**: Include previous state in event properties for better analytics (e.g., previous_status)
